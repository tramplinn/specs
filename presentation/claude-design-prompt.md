# Промпт для Claude Design: презентация «Трамплин»

Ниже — готовый текст для Claude Design. Вместе с ним приложи файлы из
этого каталога:

- `brand/logo.svg` — логотип: знак + слово «трамплин»;
- `brand/brandmark.svg`, `brand/brandmark.png` — только знак (дуга с точкой);
- `docs/arch.png` — схема архитектуры;
- `screenshots/*.png` — 18 скриншотов интерфейса (список ниже).

---

## Промпт

Сделай презентацию-питч учебной платформы **«Трамплин»** (tramplinn.tech) —
16:9, 14–16 слайдов, на русском. Аудитория — преподаватели и руководство
учебных заведений, а также технические эксперты, которые оценивают проект.
Задача презентации — показать, какую проблему решает платформа, как она
выглядит вживую и почему ей можно доверять технически.

**Важно:** не упоминай никакие конкретные учебные заведения (никаких «ННГУ»,
«колледж ННГУ» и т. п.) — ни в тексте, ни в подписях, ни в колонтитулах.
Аудиторию называй обобщённо: «колледжи и вузы», «учебное заведение».

### Стиль — бери его из скриншотов интерфейса

Презентация должна выглядеть как продолжение интерфейса продукта: тёмная,
спокойная, «продуктовая», без стоковых картинок и иллюстраций людей.

- **Фон:** `#0d0e10`, карточки `#17181c`, приподнятые элементы `#1f2127`,
  границы `#26282e` / `#30333b`. Мягкий градиент от `#17181c` к `#0d0e10`
  и слабое синее свечение (radial, `#2b7fff` ~14% прозрачности) в углу.
- **Текст:** основной `#f2f3f5`, вторичный `#a4a9b3`, подписи `#8a8f98`.
- **Акцент:** синий `#4b93ff` (кнопки/hover `#2b7fff`, мягкая подложка
  `#16233a`). Дополнительные метки: бирюзовый `#3ccbe3`
  (практика), фиолетовый `#b777f0` (AI), зелёный `#30d158` (успех/
  «решено»), оранжевый — для «средняя сложность», красный `#ff453a` — для
  «сложная».
- **Шрифт:** Inter (заголовки 600, плотный трекинг, крупно), моно —
  JetBrains Mono для кода и технических деталей.
- **Логотип и бренд:** слово «трамплин» строчными, синим `#4b93ff`, рядом
  знак-дуга с точкой — используй готовые файлы `brand/logo.svg` и
  `brand/brandmark.svg`, не рисуй логотип заново. Слоган:
  «знания становятся **практикой.**» — вторая строка синим.
- **Приёмы:** скругления 16–24 px, тонкие обводки, точечная сетка
  (точки `#8a8f98` ~17% с шагом 32 px) как фон для схем, «таблетки»-чипы
  с цветной точкой («курсы / практика / AI-помощь»),
  карточки-шаги, соединённые тонкими линиями `#35445e` (как
  «изучай → пробуй → двигайся выше»). Заголовки разделов — строчными, как
  в интерфейсе («курсы», «алгосы», «моё обучение»).
- **Скриншоты:** вставляй в «окно» — карточка `#17181c`, радиус 16 px,
  обводка `#26282e`, лёгкая тень и синее свечение позади. Можно кадрировать
  (левый сайдбар часто не нужен) и выделять зону синей рамкой `#4b93ff`
  с короткой выноской. Скриншоты не перерисовывай и не «улучшай» — это
  реальный продукт.
- **Размер скриншотов — главное правило.** Интерфейс снят увеличенным
  (×1.5–1.75) и уже обрезан до полезной зоны, но на слайде текст всё равно
  должен оставаться читаемым с проектора:
  - главный скриншот слайда — не уже ~60 % ширины слайда, лучше 65–75 %;
  - на слайде максимум 1–2 крупных скриншота; третий и дальше — маленькие
    превью-«карточки» без требования читаемости, только как иллюстрация;
  - не уменьшай скриншоты, чтобы уместить больше — лучше раздели на два
    слайда или дополнительно кадрируй;
  - не растягивай кадр больше его исходного размера (ширины в пикселях
    указаны в таблице ниже) — иначе он станет мыльным.

### Структура

1. **Титульный слайд.** Логотип, надстрочник
   «УЧЕБНАЯ ПЛАТФОРМА», заголовок «знания становятся / практикой.»,
   подзаголовок «От первого урока до работающего кода.», три чипа
   «курсы · практика · AI-помощь», справа — схема из трёх карточек
   «изучай → пробуй → двигайся выше» на точечной сетке.
2. **Проблема.** Обучение построено вокруг слайдов и конспектов: пара
   уходит на переписывание лекции, код пишется в тетради и не проверяется,
   вопрос можно задать только преподавателю и только на паре, преподаватель
   готовит материалы вручную.
3. **Было → стало.** Таблица из двух колонок (тускло слева, ярко справа):
   - презентация на паре → интерактивный урок с кодом, доступный всегда;
   - конспект в тетрадь → материал уже на платформе, пара — на практику;
   - код на слайде → код запускается и проверяется прямо в браузере;
   - вопросы только на паре → AI-тьютор по материалу урока 24/7;
   - проверка раз в семестр → тесты и задачи с автопроверкой после урока;
   - всё вручную → AI-ассистент и AI-агенты через MCP помогают авторам.
4. **Для кого.** Три карточки-роли: студент, преподаватель, администратор
   (+ маленькая четвёртая: AI-агент, действующий от имени преподавателя).
5. **Маршрут обучения.** `04-course-map.png` — крупно. Подпись: карта курса
   связывает модули в маршрут, связи — рекомендованный порядок, а не замок;
   прогресс по каждому модулю. Мини-превью `02-courses-catalog.png` и
   `03-my-learning.png` («продолжить» / «пройдено»).
6. **Урок и тесты.** `05-lesson.png` + `06-quiz.png` + `07-quiz-grouping.png`: Markdown с
   подсветкой кода, 6 типов вопросов (один/несколько ответов, текст,
   сопоставление, группировка, файл), учёт в прогрессе.
7. **AI-тьютор.** `08-tutor-chat.png` (кадр маленький — показывай его в размере не больше ~35% ширины слайда, рядом с крупным тезисом): объясняет материал урока, работает
   24/7, с квотами на запросы (стоимость AI под контролем). Фиолетовый
   акцент.
8. **Практика: алгоритмы.** `10-algorithm-solve.png` крупно, рядом
   `09-algorithms-list.png`: условие, редактор и запуск на одном экране,
   несколько языков (C++, Python, Go и др.), свой ввод, тест-кейсы,
   режимы practice и mock interview. Код исполняется в изолированной
   песочнице. Бирюзовый акцент.
9. **Сообщество и проекты.** `11-people.png`, `12-profile.png`,
   `13-projects.png`, `14-project-page.png` (крупно 1–2, остальные — превью): публичные профили с
   прогрессом, проекты студентов с README, командой, статусами и
   ссылками (GitHub, демо, Figma), приглашения в команду.
10. **Преподавание.** `15-manage-content.png` + `16-lesson-editor.png` +
    `17-algorithm-editor.png` (крупно — редактор урока): треки → курсы → модули → уроки, редактор с
    живым предпросмотром Markdown, редактор задач с тестами, черновики и
    публикация. AI-ассистент автора предлагает правки — преподаватель
    принимает или отклоняет.
11. **Курс через AI-агента (MCP).** Схема из 4 шагов на точечной сетке:
    вход под преподавателем (OAuth 2.1 + PKCE) → агент читает курс →
    validate → preview diff → apply. Тезисы: ничего не удаляется,
    ничего не публикуется само, всё остаётся черновиком, планы
    идемпотентны. Подключается к Claude Code, Codex и любым MCP-клиентам.
    Принцип крупно: «AI предлагает — человек решает».
12. **Администрирование.** `18-admin-users.png` + `01-overview-news.png`:
    роли (студент / преподаватель / админ), статусы доступа, лента новостей
    с редакцией.
13. **Под капотом.** `docs/arch.png` + таблица пяти сервисов:
    frontend (Vue 3 · TypeScript · Vite · Pinia), backend (FastAPI ·
    PostgreSQL · pgvector · Redis), email-service (FastStream · RabbitMQ),
    mcp-server (FastMCP · OAuth 2.1 + PKCE), infra (Docker Compose · Caddy ·
    Piston · Grafana). Принципы: backend — единственный владелец данных;
    запуск кода изолирован и не видит базу; вход по email-коду, GitHub,
    Яндекс.
14. **Качество.** Чипы-факты: строгий mypy, pytest с покрытием ≥ 90 %,
    ESLint/Prettier/Vitest, CI/CD с security-сканированием и immutable-
    образами, мониторинг Prometheus + Loki + Grafana.
15. **Ценность и метрики.** Три колонки (студенты / преподаватели /
    учебное заведение) и ниже — целевые метрики пилота **с явной пометкой
    «гипотезы»**: WAU ≥ 60 % зачисленных, ≥ 50 % завершённых уроков,
    ≥ 3 задачи на студента в неделю, −40 % времени на подготовку урока,
    ≥ 50 % принятых предложений AI-ассистента.
16. **Финал.** Логотип, «знания становятся практикой.», адрес
    tramplinn.tech, крупная синяя кнопка-«таблетка» «попробовать».

### Правила по тексту

- На слайде — один заголовок-мысль и 2–4 коротких тезиса, без абзацев.
- Цифры и названия бери только из этого промпта; ничего не выдумывай
  (никаких числа пользователей, отзывов, партнёров, логотипов вузов).
- Метрики — только как цели-гипотезы, не как достигнутые результаты.
- Имена людей на скриншотах — демо-данные, на них не делай акцент.
