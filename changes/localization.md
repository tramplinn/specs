# Двуязычная платформа: русский и английский

Статус: спецификация к реализации. Описанное ниже — целевое поведение,
а не уже доступные возможности. Языки первой версии: `ru` и `en`.

Связанные документы: [продукты](../product/products.md), [пользовательские кейсы](../product/use-cases.md).
Документ определяет продуктовые правила для frontend, backend и интеграций.
Схемы таблиц, миграции, конкретные API-маршруты и задачи реализации оформляются
рядом с кодом соответствующих сервисов.

## 1. Цель

Пользователь выбирает русский или английский и получает интерфейс и материалы
на выбранном языке. Преподаватель хранит, редактирует и публикует обе версии
одного материала. Автоматический перевод помогает подготовить вторую версию,
а опубликованный результат проверяет преподаватель.

Языковые версии относятся к одной сущности: у курса, урока, теста и задачи
сохраняются общие идентификаторы, адреса, связи и прогресс. Переключение языка
не создаёт второй курс и не требует повторного прохождения.

## 2. Объём перевода

| Область | Что переводится |
| --- | --- |
| Интерфейс всех ролей | Навигация, страницы, формы, редакторы, админка, кнопки, подсказки, пустые состояния, подтверждения, ошибки и подписи для скринридеров |
| Треки, курсы, модули | Названия, описания, краткие аннотации |
| Уроки | Заголовки, Markdown-текст, подписи и alt-тексты, вопросы и ответы карточек собеседования |
| Тесты | Названия, формулировки, подписи вариантов, элементов сопоставления и группировки, объяснения, языковые варианты допустимых текстовых ответов |
| Алгоритмические задачи | Названия, условия, пояснения ограничений и примеров, подписи |
| Наборы практики | Названия, описания и инструкции |
| Новости | Заголовки, аннотации, основной текст, подписи и alt-тексты |
| Справочные подписи | Названия ролей, статусов, сложностей, направлений и отображаемые названия редакционных тегов |
| Служебные сообщения | Письма входа и уведомлений, ошибки API, сообщения о квотах и результатах операций |
| AI-функции | Язык новых ответов тьютора и ассистента автора, пояснения рекомендаций |

Даты, числа, длительности и формы множественного числа соответствуют языку
интерфейса; язык сам по себе не меняет часовой пояс пользователя.

### Границы

- Имена людей, логины, названия компаний и вузов, бренды и пользовательские
  профили сохраняются в авторском виде. Пользовательские ответы, решения,
  сообщения чата и обращения обратной связи не переводятся автоматически.
- Идентификаторы, slug, URL, ключи вариантов ответа, формулы, команды, API-имена,
  содержимое блоков кода, входные и выходные данные примеров и тестов сохраняются.
  Комментарии внутри исполняемого кода также не меняются автопереводом.
- Язык программирования (`python`, `go` и т. п.) независим от языка материала.
- Изображения, PDF, видео и внешние сайты не переводятся автоматически.
  Преподаватель может прикрепить отдельный файл для каждой языковой версии;
  если используется общий файл с текстом на другом языке, это обозначается.
  При проверке перевода преподаватель проверяет и такие вложения.
- Тексты сторонних OAuth-страниц и вывод компилятора остаются в исходном виде;
  пояснения платформы вокруг них локализуются.
- Новые языки, автоматический перевод пользовательского контента и отдельные
  программы курса для разных языков не входят в первую версию.

## 3. Выбор языка

1. Переключатель «Русский / English» доступен в шапке на всех страницах,
   включая мобильную версию и вход без регистрации. Он управляется клавиатурой
   и показывает текущий язык.
2. Язык интерфейса и запрашиваемый язык материалов переключаются вместе.
   В авторском редакторе есть отдельный выбор редактируемой версии RU / EN.
3. Для новой сессии приоритет: явно указанный язык ссылки → сохранённое
   предпочтение авторизованного пользователя → сохранённый выбор браузера → `ru`.
   Автоопределение по языку браузера в первой версии не применяется.
4. Ручной выбор немедленно применяется в текущей сессии и сохраняется локально;
   у вошедшего пользователя он также сохраняется в профиле для других устройств.
   При входе текущий явно сделанный выбор переносится в профиль; если выбора
   не было, применяется предпочтение профиля. Открытие ссылки с языком само
   по себе не переписывает постоянное предпочтение.
5. Если сохранение предпочтения на сервере не удалось, текущий язык остаётся
   выбранным; пользователь видит сообщение о несохранённой настройке.
   Недоступность локального хранилища не препятствует работе переключателя.
6. Ссылкой можно поделиться с явно заданным `locale=ru` или `locale=en`.
   Параметр сохраняется при переходах внутри платформы и возврате из OAuth.
   Старые адреса продолжают открываться. Неизвестный язык в адресе страницы
   игнорируется с переходом к обычному выбору; некорректный язык в API отклоняется.
7. Переключение не требует полной перезагрузки, сохраняет текущую страницу,
   фильтры, раскрытые блоки и введённые данные. Устаревший ответ запроса для
   предыдущего языка не может заменить материал после переключения.

## 4. Хранение двух версий

У материала есть общая часть и отдельная сохранённая версия на каждый язык.
Перевод не вычисляется при каждом открытии страницы и не хранится только
в браузере. Обе версии можно создать и редактировать полностью вручную.

| Общие данные | Данные языковой версии |
| --- | --- |
| ID, slug, связи, порядок, доступ, структурная редакция | Язык, заголовки, описания, тексты и языковые вложения |
| Состав курса, типы вопросов, ключи вариантов и элементов | Тексты вопросов и вариантов с привязкой к общим ключам |
| Баллы, правильные ключи, лимиты, тест-кейсы и код | Допустимые текстовые ответы для данного языка |
| Прогресс, попытки, сессии и решения | Редакция текста, черновик, опубликованная редакция, история правок |

Исходный язык задаётся при создании (`ru` или `en`); имеющийся контент при
миграции считается русским. Материал можно создать сначала на английском.
В первой версии исходный язык после создания не меняется. Язык выбранной
вкладки редактора не меняет исходный язык.

Для версии известны: автор и время правки, номер редакции, способ создания
(вручную или перевод), язык и редакция источника перевода, кто и когда
проверил и опубликовал результат. Ручная правка не стирает происхождение.
История позволяет посмотреть предыдущие редакции и восстановить одну
из них новым черновиком.

Для урока HTML и карточки собеседования производятся из Markdown именно
этой языковой редакции; для задачи HTML производится из её условия.
Сохранение EN не перегенерирует производные данные RU и наоборот.

## 5. Черновики, публикация и актуальность

Существуют две независимые оси: публикация версии и её актуальность
относительно источника. Признак «устарел» не является заменой статуса публикации.

| Состояние версии | Что видит преподаватель | Что доступно читателю |
| --- | --- | --- |
| Отсутствует | Предложение создать вручную или перевести | Правило замены из раздела 6 |
| Черновик | Редактирование, предпросмотр и проверка | Последняя опубликованная редакция, если есть |
| Опубликована | Опубликованная редакция и возможность нового черновика | Опубликованная редакция |
| Снята с публикации | Сохранённый текст и история | Правило замены из раздела 6 |

- Сохранение правки создаёт/обновляет черновик; читатели не видят незавершённую
  правку уже опубликованного текста. Публикация — отдельное действие.
- RU и EN публикуются независимо. Отсутствие EN не мешает публикации RU.
  Проверка разрешений и доступности самой сущности и её родителей сохраняется:
  публикация перевода не открывает скрытый курс или черновик урока.
- Публикация допустима только при заполнении обязательных полей, валидном
  Markdown/структуре и явном подтверждении преподавателем проверки версии.
  Поля, необязательные по смыслу, могут оставаться пустыми.
- Публикация курса каскадом явно указывает язык и заранее показывает список
  затрагиваемых версий. Она не публикует черновики другого языка и не создаёт
  отсутствующие переводы. Снятие всей сущности с публикации скрывает оба языка.
- При изменении источника редактор показывает, относительно какой редакции
  сделан перевод, и diff. После публикации нового исходного текста старый
  опубликованный перевод помечается устаревшим, но остаётся читаемым с отметкой
  «Перевод может отличаться от обновлённого оригинала» и ссылкой на оригинал.
  Преподаватель может обновить перевод, подтвердить соответствие без изменения
  текста или снять его с публикации. Черновик источника не меняет публичный статус.
- Любая публикация правки одной версии уведомляет редактора другой о необходимости
  сверки, в том числе при независимых ручных правках EN. Подтверждение сверки
  привязывается к конкретным редакциям и само по себе не запускает новую сверку.
- Изменение общей структуры (состава вопросов, ключей, правил проверки)
  подготавливается как новая структурная редакция. При её публикации переводы,
  не проверенные для этой структуры, не выдаются новым читателям до проверки.
  Совместимость требуется сверх текстовой актуальности. Старые попытки остаются
  привязаны к прежней структуре; детали — в разделе 9.

## 6. Какой материал получает пользователь

Выдаётся целая опубликованная и структурно совместимая языковая версия,
а не смесь заполненных полей RU и EN.

| Ситуация | Поведение |
| --- | --- |
| Запрошенная версия опубликована и совместима | Выдать её; при устаревании показать отметку |
| Запрошенная отсутствует, только в черновике, снята или несовместима | Выдать доступную опубликованную версию исходного языка |
| Исходная недоступна, но другой язык опубликован и совместим | Выдать доступную версию другого языка |
| Ни один язык недоступен | Материал не включается в публичные списки; по прямой ссылке — обычное состояние недоступного материала |

Замена сопровождается заметной подписью на языке интерфейса, например:
«Английская версия пока недоступна. Показана русская». Выбранный язык интерфейса
и предпочтение пользователя при этом не меняются. Черновик никогда не
используется как замена для читателя, в том числе преподавателя вне режима preview.

Правило применяется отдельно к каждой сущности: курс может иметь EN-описание
и ещё не переведённые уроки. В списке видны доступные языки конкретного материала;
на странице явно указан фактически показанный язык. Внутри одного теста
не смешиваются вопросы и варианты из разных языковых версий.

Клиент получает запрошенный и фактический язык, доступные опубликованные языки,
редакцию и признаки замены/устаревания. Эти данные нужны также для каталога,
карты курса, новостей, поиска и карточек рекомендаций. Ранжирование рекомендаций
и прогресс относятся к общей сущности; две версии не создают дубликаты выдачи.
Поиск учитывает тексты выбранного языка и доступной замены; результаты и
их фрагменты проходят те же правила публикации и доступа.

## 7. Редактор преподавателя

- В каждом редакторе есть вкладки RU / EN со статусом, актуальностью и датой
  последней правки. Преподаватель может редактировать обе версии при наличии
  обычного права редактирования материала; отдельная роль переводчика не нужна.
  Для новостей действуют существующие права редакции.
- Язык интерфейса редактора не ограничивает язык текста: с русским интерфейсом
  можно редактировать английскую версию и наоборот.
- Действия явно называют цель: «Сохранить EN», «Опубликовать RU»,
  «Перевести RU → EN». Выбор вкладки не копирует текст из другого языка.
- Общие настройки отделены от языковых полей и подписаны «Для обеих версий».
  Изменения структуры заранее показывают, какие переводы потребуют проверки.
- При смене языковой вкладки несохранённый текст остаётся отдельным локальным
  черновиком этой вкладки. При уходе со страницы действует защита несохранённых
  изменений для обеих версий; смена языка интерфейса также их не теряет.
- Можно открыть исходник и перевод рядом, увидеть diff с исходной редакцией,
  проверить форматирование и вложения, посмотреть точный preview выбранной
  версии. Preview не подставляет другой язык вместо пустого перевода.
- Сохранение проверяет редакцию: параллельная правка той же версии другим
  преподавателем вызывает конфликт с возможностью сравнения, а не перезапись.
  Независимые текстовые правки RU и EN не конфликтуют; изменение общих данных
  проверяется отдельно.
- В списке материалов есть фильтры «нет EN/RU», «черновик перевода»,
  «нужна сверка», «несовместим со структурой» и индикаторы готовности.

## 8. Автоматический перевод

1. Преподаватель выбирает сохранённую исходную редакцию и целевой язык.
   Можно перевести материал или запустить подготовку переводов для курса.
   Операция не требует предварительной публикации исходного текста.
2. Перевод выполняется в фоне. Видны ожидание, выполнение, успех или ошибка;
   уход со страницы не отменяет работу. Повторная отправка той же операции
   не создаёт конкурирующих дублей. Лимиты объёма и повторных попыток ограничены.
3. Переводчик обрабатывает только разрешённые текстовые поля. Он сохраняет
   структуру Markdown, ссылки, директивы карточек, ключи и защищённые фрагменты.
   Код, скрытые тесты и эталонные решения не входят в переводимый payload.
   Для текстовых вопросов допустимые ответы переводятся отдельным закрытым
   полем и доступны только автору и серверной проверке.
4. Результат сначала показывается как предложение с diff. Применение требует
   явного действия преподавателя и сохраняет черновик. При существующем
   переводе доступны принятие/отклонение правок; ручные изменения не затираются
   ни фоновым заданием, ни повторной генерацией.
5. Задание фиксирует редакции источника и целевой версии. Если они изменились
   во время работы, предложение помечается как конфликтующее/устаревшее;
   автоматическое применение запрещено. Преподаватель сравнивает или запускает
   перевод заново. Ошибка сервиса не меняет сохранённые тексты.
6. Перед публикацией преподаватель проверяет смысл, терминологию, форматирование,
   текстовые ответы и вложения. Машинный перевод сам себя не публикует.
7. Массовая операция показывает результат по каждому материалу, сохраняет
   успешные предложения при частичном сбое и позволяет повторить неудавшиеся.
   Пакетное применение и публикация требуют отдельного подтверждения списка.

Провайдер/модель перевода и численные лимиты выбираются в техническом PRD.
Продуктовая зависимость: перевод не блокирует чтение, ручной авторинг и публикацию.

## 9. Тесты, практика и прогресс

- Языки делят одну структуру теста и стабильные ключи вопросов, вариантов,
  пар и групп. Перевод подписи не меняет правильный вариант и начисление баллов.
  Если существующий контракт использует текст как ключ, при реализации он
  переводится на стабильные ключи с совместимой миграцией старых попыток.
- Для свободного текстового ответа допустимые строки и языковые правила
  нормализации задаются и проверяются отдельно для RU и EN. Это серверные
  данные; они не попадают в публичные payload, preview студента или подсказки
  до того момента, когда их раскрытие разрешено правилами теста.
- В начале попытки сервер фиксирует фактический язык и неизменяемую редакцию
  теста, включая структуру и правила оценки. При замене EN на RU попытка
  считается русской. Ответы оцениваются по этой редакции, даже если преподаватель
  позднее изменил текст, ответы или снял версию с публикации.
- При смене языка интерфейса во время незавершённой попытки язык самого теста
  остаётся прежним; показывается пояснение. Ответы не теряются. Для прохождения
  на другом языке пользователь явно начинает новую попытку после подтверждения
  выхода из текущей; незавершённая попытка не становится автоматически неудачной.
- В алгоритмической практике смена языка условия сохраняет код, выбранный язык
  программирования, результаты запусков, сессию и таймер. Если условия для
  зафиксированной редакции сессии на другом языке нет, остаётся прежнее условие
  с пояснением. Лимиты и проверочные тесты общие для языков.
- Прогресс урока, завершение курса, зачёт задачи и история попыток общие.
  Смена языка или публикация нового перевода не обнуляет достижения и не
  удваивает статистику. История показывает язык и редакцию конкретной попытки.

## 10. Сопутствующие функции и контракты

- **Frontend:** единый словарь RU/EN для всех системных строк, включая
  динамические уведомления и валидацию. Полнота обоих словарей проверяется;
  запасной RU-текст при дефекте не считается выполненным переводом интерфейса.
  Обновляются `html lang`, заголовок страницы и языковые атрибуты материала,
  особенно когда язык содержимого отличается от языка интерфейса.
- **API:** чтение явно принимает язык и возвращает метаданные из раздела 6;
  запрос без языка для совместимости означает `ru`. Авторские операции явно
  адресуют язык и редакцию. Чтение авторской версии точно и не использует замену.
  На переходный период старые операции без языка относятся только к RU и не
  могут изменять EN; срок поддержки определяется планом миграции.
- **Ошибки:** стабильный код и параметры отделены от переведённого сообщения.
  Интерфейс не разбирает русские тексты для определения типа ошибки; неизвестные
  и инфраструктурные ошибки имеют локализованное общее сообщение.
- **Кэш и поиск:** учитывают язык, опубликованную редакцию и доступ пользователя.
  Публикация/снятие/смена совместимости обновляет выдачу и для языка, который
  использовал материал как замену. Публичный кэш не содержит авторских черновиков.
- **AI-тьютор:** получает реально показанную опубликованную редакцию урока
  и язык ответа пользователя. Новые ответы следуют выбранному языку, даже
  если материал показан на другом; история не переписывается. Начатый поток
  заканчивается на языке начала запроса, следующие запросы используют новый.
- **AI-ассистент автора:** получает выбранную авторскую версию и возвращает
  правки именно для её языка и редакции; применение проходит обычный diff
  и проверку конфликтов. Другая языковая версия не перезаписывается.
- **Письма:** код входа приходит на языке запроса входа; последующие уведомления —
  на сохранённом языке профиля, по умолчанию RU. Backend готовит локализованные
  тему и текст до постановки в очередь; email-service доставляет готовое письмо.
  Повтор доставки не меняет его язык.
- **MCP:** планы и preview явно показывают язык и редакцию, apply проверяет
  конфликт и действует только на выбранную версию. Чтение и запись проходят
  через backend с обычными правами; обязательный цикл validate → preview →
  подтверждение → apply сохраняется. Общие slug обеспечивают идемпотентность
  в пределах сущности и языка.

## 11. Перенос существующих материалов и выпуск

1. Сохранить весь текущий контент как RU с исходным языком RU, прежними ID,
   slug, связями, статусами, датами публикации и прогрессом. Для имеющихся
   опубликованных материалов создать опубликованную RU-редакцию; EN отсутствует.
   Производные данные и вложения должны остаться связаны с правильной версией.
2. Ввести хранение версий, правила чтения, отдельные черновики, историю,
   проверку конфликтов и миграцию ключей тестов. Старые попытки пометить RU;
   если их исходный снимок нельзя восстановить, сохранить результат и обозначить
   отсутствие исторической редакции, не выдавать текущий текст за исторический.
3. Добавить преподавательский RU/EN-редактор, независимую публикацию и preview.
   Проверить ручное создание полного EN-материала до подключения автоперевода.
4. Подготовить словари всех экранов, переключение языка, локализованную выдачу,
   письма, AI-функции и MCP. До готовности публичного сценария переключатель
   доступен только для проверки командой.
5. Подключить фоновые переводы, выполнить проверяемое наполнение EN и проверку
   преподавателями. Частичная готовность контента допустима только с явными
   отметками замены; она не должна маскироваться как полный перевод каталога.
6. Выпустить после проверки критериев ниже. Отключение EN при проблеме должно
   возвращать интерфейс и чтение к RU, сохраняя EN-тексты, историю и прогресс;
   разрушительное удаление переводов не является способом отката.

Этапы не сокращают целевой объём: результат включает все области раздела 2.
Открытые технические решения: схема версий и снимков, очередь переводов,
провайдер и лимиты, миграция клиентов. Поведение RU/EN, публикации и замены
зафиксировано этой спецификацией и не зависит от выбора этих инструментов.

## 12. Критерии приёмки

1. Гость и вошедший пользователь переключают RU/EN на desktop и mobile;
   работают сохранение, приоритет ссылки/профиля/браузера, возврат из OAuth,
   перезагрузка и сценарий с недоступным хранилищем.
2. Все экраны студента, преподавателя и администратора, включая ошибки,
   accessibility-подписи, даты и числовые формы, доступны на обоих языках.
   Авторские тексты и исключения раздела 2 не считаются строками интерфейса.
3. Для каждого типа материала из раздела 2 можно сохранить разные RU/EN-тексты,
   опубликовать каждый отдельно и получить нужный текст на одной и той же ссылке.
   Проверяется в том числе материал, изначально созданный на EN.
4. Отсутствующий, черновой, снятый и структурно несовместимый перевод дают
   предписанную замену с правильными метаданными. Ни один публичный экран,
   поиск, рекомендация или кэш не раскрывает черновик или закрытый материал.
5. Правка EN не меняет RU; правка опубликованного текста до новой публикации
   не видна читателю. Работают история, восстановление, независимые черновики
   вкладок и обнаружение параллельных правок одной редакции.
6. Обновление источника вызывает сверку перевода; текстовая устарелость
   отличается от структурной несовместимости. Каскадная публикация RU не
   публикует EN и показывает заранее затрагиваемые материалы.
7. Автоперевод работает в обе стороны, предлагает diff и не публикует результат.
   Проверяются сбой, повтор, частичный успех пакета, изменившийся источник
   и ручная правка цели во время генерации; ни один случай не теряет правки.
8. Markdown, директивы карточек, код, URL, формулы, ключи ответов и тест-кейсы
   не повреждаются переводом. Производные HTML/карточки изолированы по языкам.
   Языковые вложения показываются корректно, общие иноязычные файлы помечаются.
9. Для всех типов вопросов равнозначные RU/EN-ответы получают одинаковые баллы;
   текстовые ответы проверяются по языку попытки. Смена UI не теряет ответы,
   смена редакции преподавателем не меняет уже начатую проверку.
10. Переключение языка в практике сохраняет код и таймер. Общие прогресс,
    зачёты и статистика не дублируются; старые попытки после миграции сохранены.
11. Поиск и рекомендации не дублируют сущности. Смена языка при медленном запросе
    и публикация перевода во время чтения не приводят к смешению языков/редакций.
12. Письма, новые ответы AI и авторские планы MCP используют нужный язык;
    язык программирования остаётся независимым. Проверяется совместимость
    запросов без языка и отсутствие влияния таких записей на EN.
13. Миграция сохраняет опубликованный RU-контент и все связи; отключение EN
    не удаляет переводы и не повреждает пользовательские данные.

## 13. Наблюдение после выпуска

Считать долю материалов с опубликованными RU/EN-версиями по типам, долю выдач
с заменой языка, количество устаревших/несовместимых переводов, ошибки и время
перевода, объём расхода провайдера и частоту ручных исправлений предложений.
В технических событиях фиксировать язык и редакцию, не полный текст материала.
Целевые значения пока не заданы: их устанавливают после инвентаризации
контента и пилота перевода, а не считают текущими показателями платформы.
