# Пользовательские кейсы

Формат: роль → цель → основной сценарий → результат. Роли описаны в
[products.md](products.md).

## Студент

### UC-S1. Выбрать курс и начать обучение
- **Цель:** найти подходящий курс и понять, с чего начать.
- **Сценарий:** входит по email-коду или через GitHub/Яндекс → открывает
  каталог треков и курсов → смотрит карту курса (модули и уроки) → начинает
  первый урок.
- **Результат:** курс в «моих», прогресс начал считаться.

### UC-S2. Пройти урок и закрепить тестом
- **Сценарий:** читает урок (Markdown, примеры кода) → проходит тест (выбор,
  ввод текста, сопоставление, группировка drag-and-drop, загрузка файла) →
  видит результат попытки и при необходимости пересдаёт.
- **Результат:** урок отмечен пройденным, прогресс по курсу обновлён.

### UC-S3. Спросить AI-тьютора по уроку
- **Сценарий:** не понял тему → открывает чат тьютора в уроке → задаёт
  вопрос → получает объяснение в контексте материала.
- **Ограничения:** дневная квота запросов; у гостя квота меньше.
- **Результат:** студент разобрался без ожидания преподавателя.

### UC-S4. Решить алгоритмическую задачу
- **Сценарий:** выбирает задачу в банке (сложность, теги) → пишет решение в
  редакторе на выбранном языке → запускает на открытых примерах → отправляет
  на проверку по скрытым тестам.
- **Результат:** вердикт по каждому тест-кейсу, задача засчитана при
  успехе.

### UC-S5. Пройти mock interview
- **Сценарий:** выбирает набор практики в режиме `mock_interview` →
  запускается сессия с таймером → решает задачи набора → сессия завершается
  по времени или вручную.
- **Результат:** итог сессии со статусом `completed`/`expired`, понимание
  готовности к собеседованию.

### UC-S6. Получить рекомендации
- **Сценарий:** открывает главную → видит подборку курсов и задач на основе
  своего прогресса и интересов.
- **Результат:** следующий шаг обучения без самостоятельного поиска.

### UC-S7. Учиться на выбранном языке
- **Статус:** целевое поведение, спецификация к реализации.
- **Сценарий:** выбирает RU или EN → получает интерфейс и опубликованные
  материалы на выбранном языке → продолжает тот же курс с прежним прогрессом.
  Если перевода нет, видит доступную версию с явной отметкой языка.
- **Результат:** язык обучения можно менять без создания второго аккаунта
  и повторного прохождения материалов. Правила незавершённых попыток —
  в [спецификации RU/EN](../changes/localization.md#9-тесты-практика-и-прогресс).

## Преподаватель

Языковые сценарии обучения и авторинга описаны в
[спецификации RU/EN](../changes/localization.md).

### UC-T1. Создать курс вручную
- **Сценарий:** создаёт курс → добавляет модули и уроки в редакторе с
  live-превью → загружает файлы и изображения → публикует.
- **Результат:** курс виден студентам; публикация каскадно применяется к
  вложенным сущностям.

### UC-T2. Собрать тест
- **Сценарий:** в редакторе тестов добавляет вопросы нужных типов, задаёт
  правильные ответы → привязывает тест к уроку.
- **Результат:** автоматическая проверка ответов студентов.

### UC-T3. Создать алгозадачу и набор практики
- **Сценарий:** пишет условие, ограничения по времени и памяти, тест-кейсы
  (открытые и скрытые), шаблоны кода для языков → собирает задачи в набор
  практики, задаёт режим и длительность.
- **Результат:** задачи доступны студентам с автопроверкой.

### UC-T4. Улучшить материал с AI-ассистентом
- **Сценарий:** в редакторе урока или задачи формулирует просьбу («упрости
  объяснение», «добавь скрытые тесты», «сделай шаблон на Go») → ассистент
  предлагает правки только нужных полей → преподаватель принимает или
  отклоняет.
- **Результат:** контент лучше, время подготовки меньше.

### UC-T5. Наполнить курс AI-агентом через MCP
- **Сценарий:** подключает MCP-сервер к своему агенту → авторизуется через
  OAuth под своей учёткой → агент читает текущий курс, готовит план →
  `validate` → `preview` (diff) → преподаватель подтверждает → `apply`.
- **Результат:** курс наполнен за минуты; применение идемпотентно, ничего не
  удаляется; агент не имеет доступа к БД напрямую.

### UC-T6. Подготовить и поддерживать две языковые версии
- **Статус:** целевое поведение, спецификация к реализации.
- **Цель:** предложить один материал на русском и английском без дублирования
  курса и прогресса.
- **Сценарий:** открывает вкладку RU или EN → создаёт текст вручную либо
  получает предложение автоперевода → проверяет diff и редактирует → сохраняет
  черновик → публикует выбранную версию. После правки оригинала сверяет перевод.
- **Результат:** студент получает опубликованную версию на выбранном языке;
  обе версии доступны преподавателю для независимых правок.

## Администратор


### UC-A1. Управлять пользователями
- **Сценарий:** находит пользователя → назначает роль (студент,
  преподаватель, админ).
- **Результат:** права соответствуют реальной роли в колледже.

### UC-A2. Публиковать новости
- **Сценарий:** создаёт новость в редакции → публикует → новость видна всем
  в ленте.
- **Результат:** единый канал объявлений платформы.

## Гость

### UC-G1. Познакомиться с платформой
- **Сценарий:** без регистрации смотрит каталог, новости и профили, пробует
  AI-тьютора в рамках гостевой квоты → регистрируется.
- **Результат:** конверсия посетителя в студента.

## Системные кейсы

### UC-X1. Доставить письмо
- **Сценарий:** backend готовит письмо (код входа, уведомление) и кладёт в
  очередь → email-service отправляет через SMTP; при сбоях SMTP срабатывает
  circuit breaker.
- **Результат:** письма доходят, сбой почты не роняет основной API.

### UC-X2. Выполнить решение изолированно
- **Сценарий:** отправка решения ставит задание в RabbitMQ → algo worker
  запускает код в Piston по тест-кейсам → результат сохраняется и
  показывается студенту.
- **Результат:** безопасный запуск недоверенного кода под нагрузкой.
